# v0.2.2 release notes

Published and verified on 2026-11-05. Version 0.2.2 adds canonical dataframe
infrastructure while retaining the governed 0.2.1 result and invalid-input
contracts.

## Canonical analytical execution

Governed eager pandas DataFrames, Polars DataFrames and PyArrow Tables remain
accepted public inputs. Analytical paths now recognize those inputs through the
private Narwhals boundary, copy only declared columns into detached canonical
Polars frames and execute dataframe work on Polars. Original source backend,
schema, row order and identity remain in provenance; pandas indexes do not define
analytical identity. Lazy and distributed inputs are rejected without collection.

Private Pandera schemas validate canonical Polars structure without coercing
values, dropping rows or mutating caller data. LSS4PY continues to own public
errors, issue codes, duplicates, timestamp precision, units, identity and
cross-column analytical semantics. ADR-0028 records the accepted boundary.

## Compatibility evidence

The complete governed neutral result payload remains exact against the
pre-migration implementation across pandas, hostile-index pandas, Polars and
PyArrow. A separate 13-case fixture preserves invalid-input acceptance,
exception classes and messages. All 28 genuine R reference cases pass, and
installed-wheel journeys retain the base, pandas, storage/PyArrow and ecosystem
boundaries.

## Measured cost

Against the Phase 1 baseline on the governed local 20,000-row corpus:

- validation adds 10–39 milliseconds;
- public `describe` adds 0.5–9.3 milliseconds;
- isolated-process high-water memory adds 25–37 MiB;
- the wheel grows by 6,136 bytes; and
- the base installation grows from 39 to 44 distributions.

The five added distributions are Pandera, packaging, typeguard, typing-inspect
and mypy_extensions. pandas and PyArrow remain absent from the base installation,
and the seven-run import medians show no meaningful regression. These
single-machine values are regression evidence rather than service-level
guarantees. Full methods, hashes and limitations are in the
[canonicalization assessment](../assessments/v022-canonicalization-evidence.md).
